Part 1: Filters and Edges

Part 1.1 — Convolutions from Scratch

I implemented 2D convolution twice: once with four nested loops (the literal, unoptimized translation of the convolution formula), and once with two loops, where the innermost multiply-and-accumulate step is replaced by a single vectorized numpy operation (np.sum(patch * flipped_kernel)). Both versions flip the kernel 180° before sliding it across the image, which is what distinguishes true convolution from cross-correlation. For a symmetric filter like a box filter, flipping makes no difference, but for an asymmetric filter like Dx = [1, 0, -1] it flips the sign convention of the result.

Both implementations support zero-padding in two modes: "same" (output matches input size, padding by kernel_size // 2 on each side) and "full" (output is n + k - 1, capturing every possible overlap between kernel and image, even a single corner touching).

Code: four loops

def convolve_four_loops(image, kernel, mode="same"):
    kh, kw = kernel.shape
    ih, iw = image.shape
    flipped_kernel = kernel[::-1, ::-1]          # flip 180 degrees

    if mode == "same":
        pad_h, pad_w = kh // 2, kw // 2
        out_h, out_w = ih, iw
    elif mode == "full":
        pad_h, pad_w = kh - 1, kw - 1
        out_h, out_w = ih + kh - 1, iw + kw - 1
    else:
        raise ValueError("mode must be 'same' or 'full'")

    padded = np.zeros((ih + 2*pad_h, iw + 2*pad_w))   # zero padding
    padded[pad_h:pad_h+ih, pad_w:pad_w+iw] = image
    output = np.zeros((out_h, out_w))

    for y in range(out_h):            # every output row
        for x in range(out_w):        # every output column
            total = 0.0
            for i in range(kh):       # every kernel row
                for j in range(kw):   # every kernel column
                    total += padded[y + i, x + j] * flipped_kernel[i, j]
            output[y, x] = total
    return output

Code: two loops

def convolve_two_loops(image, kernel, mode="same"):
    kh, kw = kernel.shape
    ih, iw = image.shape
    flipped = kernel[::-1, ::-1]

    if mode == "same":
        pad_h, pad_w = kh // 2, kw // 2
        out_h, out_w = ih, iw
    elif mode == "full":
        pad_h, pad_w = kh - 1, kw - 1
        out_h, out_w = ih + kh - 1, iw + kw - 1
    else:
        raise ValueError("mode must be 'same' or 'full'")

    padded = np.zeros((ih + 2*pad_h, iw + 2*pad_w))
    padded[pad_h:pad_h+ih, pad_w:pad_w+iw] = image
    output = np.zeros((out_h, out_w))

    for y in range(out_h):
        for x in range(out_w):
            patch = padded[y:y+kh, x:x+kw]
            output[y, x] = np.sum(patch * flipped)   # dot product, vectorized
    return output

Even on the tiny patch, scipy is roughly 33× faster than my two-loop version. The reason is where the work happens: the four-loop version executes every multiply-add (kernel_height × kernel_width per output pixel) as interpreted Python. The two-loop version still loops over every output pixel in Python, but hands each kh × kw window to numpy as one vectorized operation, so the multiplication itself runs in compiled C. scipy.signal.convolve2d pushes both loops into compiled code, which is why it wins by another large factor.

How boundaries are handled

I pad the image with zeros by kernel_size // 2 on each side before sliding the kernel, which is equivalent to SciPy's boundary="fill", fillvalue=0. This keeps the output the same size as the input, but pixels near the border get averaged with fake zeros, which pulls their brightness down. This shows up as a faint dark frame around blurred results (visible in the 9×9 box-filtered selfie). Mirroring the image at the edge (boundary="symm") avoids this artifact, which is why I switched to "symm" padding from Part 2.1 onward for blurring.

Part 1.2 — Finite Difference Operator

Using the standard cameraman test image, I computed the partial derivatives Dx and Dy by convolving with the finite-difference operators [1, 0, -1] (horizontal) and its transpose (vertical). Combining them into the gradient magnitude, sqrt(Dx² + Dy²), gives one "edge strength" value per pixel, independent of edge direction.

Part 1.3 — Derivative of Gaussian (DoG) Filter

The raw finite-difference edges from Part 1.2 are noisy because differentiation amplifies high-frequency content indiscriminately, including sensor noise. The fix is to smooth with a Gaussian before differentiating. I built the 2D Gaussian with cv2.getGaussianKernel() (ksize=9, sigma=2) to get a 1D bell curve, then took its outer product with its own transpose.

2D Gaussian kernel (images/p13_gauss.png)

After blurring the cameraman and repeating the Dx/Dy/gradient-magnitude pipeline, the useful threshold dropped from 0.15 (unblurred) to 0.05 (blurred). Blurring spreads each brightness jump across more pixels, which lowers the peak gradient at every edge. I confirmed 0.05 with a finer sweep from 0.01 to 0.06: below it the grass gets speckly again, and above it the faint skyline starts to fade.

What differences do you see?

Blurring first produces edges that are noise-free and continuous rather than speckled and fragmented, at the cost of localization: edges become a few pixels thicker, and very fine details (like small camera knobs) start to merge. This is the smoothing-vs-precision tradeoff: noise robustness is bought by sacrificing some positional sharpness.

Folding two convolutions into one (Derivative of Gaussian)

Because convolution is associative, Dx * (G * I) = (Dx * G) * I. Rather than blurring and then differentiating (two convolutions over the image), I convolved the small Gaussian kernel directly with Dx and Dy to get two combined DoG filters, and applied each to the original image in a single convolution.

DoG_x filter (images/p13_dogx.png)

Verification

Comparing the single-DoG result against the two-step blur-then-differentiate result:

Mean absolute difference (whole image):     0.0018
Max absolute difference (whole image):      0.35
Max absolute difference (interior only):    7.2e-16

The whole-image comparison has a small mean but a larger max, which is the signature of a boundary-only discrepancy rather than a real error. Restricting to the interior (cropping a border as wide as the kernel) gives a max difference of 7.2e-16, which is floating-point noise, so the two methods are mathematically identical there. The mismatch at the border exists because the two-step method zero-pads twice (once per convolution) while the single-DoG method pads only once, so they make different assumptions about what lies outside the image.

Part 2: Applications

Part 2.1 — Image "Sharpening" (Unsharp Masking)

A Gaussian blur is a low-pass filter: it keeps only the smooth, low-frequency content. Subtracting the blurred image from the original isolates what was removed, the high-frequency detail. Since an image tends to look sharper when its high frequencies are stronger, I add a scaled copy of that residual back to the original:

sharpened = image + alpha * (image - blur(image))

This collapses into a single convolution kernel, (1 + alpha) * impulse - alpha * gaussian, though I implemented the explicit multi-step version for clarity. I blur with boundary="symm" so zero-padding doesn't create a dark border that then gets amplified, and clip results to [0, 1].

Taj Mahal: original / blurred / high-frequency residual / sharpened, alpha=1.0 (images/p21_taj_pipeline.png)

Varying the sharpening amount

Alpha sweep 0.5 / 1.0 / 2.0 / 4.0 (images/p21_taj_alpha.png)

At alpha=4.0, oversharpening artifacts appear: the sky and flat marble walls, which should be nearly featureless, pick up a grainy texture. Unsharp masking amplifies all high-frequency content equally, including the small amount of sensor noise present even in flat regions; it cannot tell detail from noise. I chose alpha = 1.0 as the featured result: a clear improvement in sharpness with no visible artifacts.

Observation:

Unsharp masking only partially restores contrast at edges that survived the blur; it cannot recover fine detail, such as marble tile texture or window lattices, that the blur destroyed. It is a perceptual sharpening technique, not a true deblurring or inverse operation. Blurring is lossy: once a frequency band has been attenuated toward zero, no linear filter can invert that loss without also amplifying the noise left at that frequency.

Part 2.2 — Hybrid Images

Overview. A hybrid image combines the high-frequency detail of one image with the low-frequency content of another. Up close, perception is dominated by high frequencies, so the detail image reads clearly; from a distance (or when shrunk), only the low frequencies survive and the interpretation flips. I low-pass one image with a Gaussian, high-pass the other as image - gaussian(image), and add them.

Alignment. I used the provided align_image_code.py, which takes two corresponding points (both eyes, in matching order) on each image and aligns center, scale, and rotation before cropping to a common size. Since plt.ginput() does not work in Google Colab's inline backend, I replaced only the point-collection step with pixel coordinates read off a gridded display of each image; every other alignment function is unmodified.

I deliberately did not apply a gain multiplier to the high-pass component, and present the result as-is because it illustrates a real limitation: hybrid images work best when both sources have comparable frequency content. When one image is mostly flat, its high-pass contribution is sparse and gets overshadowed by the other image's low frequencies, no matter how the sigmas are tuned. Amplifying the high-pass term before combining would be the separate fix for that.

Part 2.3 — Gaussian and Laplacian Stacks

A stack behaves like a pyramid without downsampling: every level stays at full resolution, growing progressively blurrier. I implemented both from scratch, with no cv2.pyrDown() or skimage.transform.pyramid_gaussian().

def gaussian_stack(image, num_levels, sigma=2):
    stack = [image.copy()]
    for level in range(1, num_levels):
        current_sigma = sigma * (2 ** (level - 1))
        blurred = low_pass(image, current_sigma)
        stack.append(blurred)
    return stack

def laplacian_stack(gauss_stack):
    lap_stack = [gauss_stack[i] - gauss_stack[i+1] for i in range(len(gauss_stack)-1)]
    lap_stack.append(gauss_stack[-1])  # low-frequency residual
    return lap_stack

Implementation detail: sigma doubles at each level (and is applied to the original image) rather than reapplying a fixed sigma to the previous level. Repeating a small blur only grows the effective radius like sqrt(n) * sigma, so the coarsest level ends up barely blurrier than an early one. Doubling produces a rapidly widening blur, which matters directly in Part 2.4: a mask that doesn't blur enough at coarse levels can't widen the blended seam.

The Laplacian levels are shown shifted by +0.5 so their near-zero values display as mid-gray. The last Laplacian level is not a difference but the final blurred Gaussian level (the low-frequency residual), which is why it looks like a real, blurry picture.

Part 2.4 — Multiresolution Blending (the Oraple)

The algorithm. With stacks instead of downsampled pyramids, splicing two Laplacian stacks at a hard boundary leaves a clearly visible seam, since no downsample/blur/upsample step softens it. Instead the mask gets its own Gaussian stack, and each frequency band is blended with the mask blurred to that band's scale:

blended[level] = imageA_laplacian[level] * mask_gaussian[level] +
                 imageB_laplacian[level] * (1 - mask_gaussian[level])
result = sum(blended[level] for all levels)

At the finest level the mask is nearly a sharp step; at the coarsest it is a wide ramp, so each band is blended over a distance proportional to its scale.

What I Learned

The most important thing I learned is that convolution, differentiation, blurring, sharpening, hybridization, and blending are the same small set of operations recombined in different orders. The associativity of convolution kept turning two-step processes into single equivalent filters: blur-then-differentiate collapsed into one Derivative-of-Gaussian filter (verified to floating-point precision), and the same blur-subtract-scale-add logic reappears in unsharp masking, in the high/low split for hybrid images, and in the Laplacian stacks behind multiresolution blending.

A second lesson, learned the hard way: the filtering math is usually the easy part, and it's rarely where things go wrong. Hybrid images worked or failed depending mostly on whether two eye coordinates were estimated to within a few pixels, and on whether both sources had comparable frequency content, not on the low-pass/high-pass code. Blends succeeded or failed on whether the two photos shared a compatible background. And the Gaussian stack only became useful for blending once I noticed that reapplying a fixed sigma barely increases the blur, and that sigma needs to grow multiplicatively across levels. What you feed a filter, and what you assume about the content just outside its boundaries, matters as much as the filter itself.
