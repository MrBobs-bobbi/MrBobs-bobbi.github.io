A.2 · Recover homographies

Matching points to a shared view

An eight-parameter transformation estimated from ten manually selected point pairs.

I clicked 10 corresponding features in each image pair, keeping their order the same in both images. Each match represents the same physical feature, even though its pixel coordinates differ. The right image is the reference.

I implemented computeH(im1_pts, im2_pts) by building a linear system and solving it with NumPy least squares. I did not use a built-in homography estimator. Each correspondence supplies two equations, so 10 matches produce 20 equations for 8 unknowns.

λ[uv1]=[h11h12h13h21h22h23h31h321][xy1]

Building the system: Ah = b

For a source point (x, y) and its target (u, v), I divide the transformed homogeneous coordinates by their third component, then rearrange the two equations. One match contributes the following rows:

[xy1000−ux−uy000xy1−vx−vy][h11h12h13h21h22h23h31h32]=[uv]

Stacking all the rows gives A with shape 20 × 8 and b with length 20. I solve for the vector h that minimizes the squared residual ||Ah − b||², then reshape its eight entries into H and set the bottom-right entry to 1. Before solving, I center and scale both point sets so their mean distance from the origin is √2. This improves numerical conditioning. I then convert the estimated matrix back to the working-image coordinates.

H=Tdst−1HnTsrc

The matrices below map left source → right reference. The displayed entries are rounded; the downloadable text files retain more precision.

def build_system(source, destination):
    #place each correspondence into two rows of the eight-unknown system
    source = np.asarray(source, dtype=np.float64)
    destination = np.asarray(destination, dtype=np.float64)
    x, y = source.T
    u, v = destination.T
    A = np.zeros((2 * len(source), 8), dtype=np.float64)
    b = np.empty(2 * len(source), dtype=np.float64)
    A[0::2, :3] = np.column_stack([x, y, np.ones(len(x))])
    A[1::2, 3:6] = np.column_stack([x, y, np.ones(len(x))])
    A[0::2, 6:] = -np.column_stack([u * x, u * y])
    A[1::2, 6:] = -np.column_stack([v * x, v * y])
    b[0::2], b[1::2] = u, v
    return A, b


def transform_points(points, H):
    #multiply homogeneous coordinates and divide by the projective denominator
    points = np.asarray(points, dtype=np.float64)
    homogeneous = np.column_stack([points, np.ones(len(points))])
    mapped = homogeneous @ np.asarray(H, dtype=np.float64).T
    if np.any(np.abs(mapped[:, 2]) < 1e-12):
        raise ValueError('A point maps to infinity. Check the homography and selections.')
    result = mapped[:, :2] / mapped[:, 2, None]
    if not np.isfinite(result).all():
        raise ValueError('Nonfinite transformed coordinates.')
    return result


def normalize_points(points):
    center = points.mean(axis=0)
    mean_distance = np.linalg.norm(points - center, axis=1).mean()
    if mean_distance < 1e-12:
        raise ValueError('The points have insufficient spatial spread.')
    scale = np.sqrt(2) / mean_distance
    T = np.array([[scale, 0, -scale * center[0]],
                  [0, scale, -scale * center[1]], [0, 0, 1]], dtype=np.float64)
    return transform_points(points, T), T


def computeH(im1_pts, im2_pts):
    #estimate a mapping from im1 coordinates to im2 coordinates
    source = np.asarray(im1_pts, dtype=np.float64)
    destination = np.asarray(im2_pts, dtype=np.float64)
    if source.ndim != 2 or source.shape[1] != 2 or source.shape != destination.shape or len(source) < 4:
        raise ValueError('Both point arrays must have matching shape (n, 2), with n >= 4.')
    if not np.isfinite(source).all() or not np.isfinite(destination).all():
        raise ValueError('Point coordinates must be finite.')
    src_n, T_src = normalize_points(source)
    dst_n, T_dst = normalize_points(destination)
    A, b = build_system(src_n, dst_n)
    h, residuals, rank, singular_values = np.linalg.lstsq(A, b, rcond=None)
    if rank < 8:
        raise ValueError('Degenerate correspondences: spread points across a two-dimensional region.')
    H_n = np.append(h, 1.0).reshape(3, 3)
    H = np.linalg.inv(T_dst) @ H_n @ T_src
    if abs(H[2, 2]) < 1e-12 or np.linalg.matrix_rank(H) < 3:
        raise ValueError('Cannot normalize a nonsingular homography from these points.')
    H /= H[2, 2]
    return H
A.3 · Warp the images

Making an angled rectangle face forward

Inverse warping with nearest neighbor and bilinear interpolation, both implemented from scratch.

I wrote warpImageNearestNeighbor(im, H) and warpImageBilinear(im, H), with a shared inverse-warping routine. For each output pixel, I apply H inverse to find its location in the source image, divide by the homogeneous coordinate, and sample its color. This avoids the holes that can occur when forward-mapped pixels miss output positions.

I treat integer coordinates as pixel centers, with (0, 0) at the top-left pixel center. For full image warps, I transform the four corners to find the output bounds. For rectification, I sample directly into the target rectangle rather than allocating a large warped background. Invalid source locations are excluded using a mask.

[xy1]∼H−1[uv1]

Two ways to sample the source

MethodImplementationExpected trade-off
Nearest neighborRound each valid coordinate using floor(value + 0.5), then read one source pixel.Fast, but can produce blocky or jagged edges.
BilinearUse the four neighboring pixels, weighted by the fractional x and y offsets.Smoother edges, with more computation and some softening.

For bilinear interpolation, I set x₀ = floor(x), y₀ = floor(y), a = x − x₀, and b = y − y₀. The upper neighbors are x₁ = min(x₀ + 1, W − 1) and y₁ = min(y₀ + 1, H − 1). Clamping the upper neighbor keeps valid border pixels instead of discarding the last row or column.

I(x, y) = (1 − a)(1 − b) I[y₀, x₀] + a(1 − b) I[y₀, x₁]
　　　　 + (1 − a)b I[y₁, x₀] + ab I[y₁, x₁]

No library interpolation or high-level perspective-warp functions are used for these steps.

Looking closer: interpolation quality

What I noticed

At first, the two interpolation results looked quite similar when I viewed the whole rectified image. The differences became much clearer in the enlarged crops.

For the painting, I looked at the diagonal edge of the red coat and where it meets the lighter clothing. Nearest neighbor creates noticeable pixel steps along these edges. Bilinear makes the transitions smoother, but the details also look slightly softer.

The difference is especially clear in the parking sign’s letters. Nearest neighbor makes their outlines look blocky and jagged. Bilinear smooths the outlines, although the letters look blurrier.

From these comparisons, I found that nearest neighbor preserves sharper pixel boundaries, while bilinear gives a smoother appearance. The sharper-looking pixels in nearest neighbor do not mean that it recovers more detail from the original photo.

In my final exported run, bilinear took about 2.9 times as long for the painting and 3.0 times as long for the sign. It needs four pixel values and a weighted average instead of one pixel lookup. Both methods finished in less than a quarter of a second per warp, so the extra waiting time was small for these examples. I would choose bilinear when I prefer smoother edges. These timings may vary between runs.

Limitations and what I learned

I assumed the aspect ratios of both objects instead of measuring them. This means that making the outlines rectangular does not guarantee that the objects have their correct physical proportions. They could still be slightly stretched or compressed.

Selecting the corners accurately also matters. A small difference in where I click can change the homography and the final alignment.

The painting still has glare and reflections, and the parking sign still has strong colored lighting. Warping changes where pixels appear, but it does not remove these effects. I also noticed that enlarging the objects cannot create detail that was missing from the original photos. Bilinear can make the result smoother, but it cannot make the original details clearer.

def sample_pixels(image, x, y, method):
    #sample only geometrically valid coordinates and keep a separate validity mask
    if method not in ('nearest', 'bilinear'):
        raise ValueError('Unknown interpolation method.')
    height, width = image.shape[:2]
    tolerance = 1e-7
    valid = np.isfinite(x) & np.isfinite(y)
    valid &= (x >= -tolerance) & (x <= width - 1 + tolerance)
    valid &= (y >= -tolerance) & (y <= height - 1 + tolerance)
    values = np.zeros((len(x), image.shape[2]), dtype=np.float32)
    if not valid.any():
        return values, valid
    xv = np.clip(x[valid], 0, width - 1)
    yv = np.clip(y[valid], 0, height - 1)
    if method == 'nearest':
        xi = np.floor(xv + 0.5).astype(np.int64)
        yi = np.floor(yv + 0.5).astype(np.int64)
        values[valid] = image[yi, xi]
    else:
        x0 = np.floor(xv).astype(np.int64)
        y0 = np.floor(yv).astype(np.int64)
        x1 = np.minimum(x0 + 1, width - 1)
        y1 = np.minimum(y0 + 1, height - 1)
        a = (xv - x0)[:, None]
        b = (yv - y0)[:, None]
        values[valid] = ((1 - a) * (1 - b) * image[y0, x0]
                         + a * (1 - b) * image[y0, x1]
                         + (1 - a) * b * image[y1, x0]
                         + a * b * image[y1, x1])
    return values, valid


def warp_to_canvas(im, H, shape, origin, method='bilinear'):
    image = np.asarray(im, dtype=np.float32)
    if image.ndim != 3 or image.shape[2] < 1:
        raise ValueError('Expected an image of shape (height, width, channels).')
    out_h, out_w = (int(v) for v in shape)
    if min(out_h, out_w) <= 0 or out_h * out_w > MAX_CANVAS_PIXELS:
        raise ValueError('Requested canvas exceeds the configured safety limit.')
    inverse = np.linalg.inv(np.asarray(H, dtype=np.float64))
    result = np.zeros((out_h, out_w, image.shape[2]), dtype=np.float32)
    mask = np.zeros((out_h, out_w), dtype=bool)
    for start in range(0, out_h, TILE_ROWS):
        stop = min(start + TILE_ROWS, out_h)
        xx, yy = np.meshgrid(np.arange(out_w, dtype=np.float64) + origin[0],
                             np.arange(start, stop, dtype=np.float64) + origin[1])
        destination = np.stack([xx.ravel(), yy.ravel(), np.ones(xx.size)])
        source = inverse @ destination
        denominator = source[2]
        finite = np.isfinite(denominator) & (np.abs(denominator) > 1e-12)
        x = np.full(xx.size, np.nan)
        y = np.full(xx.size, np.nan)
        np.divide(source[0], denominator, out=x, where=finite)
        np.divide(source[1], denominator, out=y, where=finite)
        colors, valid = sample_pixels(image, x, y, method)
        result[start:stop] = colors.reshape(stop - start, out_w, image.shape[2])
        mask[start:stop] = valid.reshape(stop - start, out_w)
    return result, mask


def warpImageNearestNeighbor(im, H, return_metadata=False):
    shape, origin = warp_bounds(im, H)
    result, mask = warp_to_canvas(im, H, shape, origin, 'nearest')
    return (result, mask, origin) if return_metadata else result


def warpImageBilinear(im, H, return_metadata=False):
    shape, origin = warp_bounds(im, H)
    result, mask = warp_to_canvas(im, H, shape, origin, 'bilinear')
    return (result, mask, origin) if return_metadata else result
A.4 · Blend into a mosaic

Where two photographs meet

Three mosaics with source images, overwrite baselines, and feathered results.

I first warped the left image into the right image’s coordinate system and placed both on a shared canvas. The right image used the identity transform. To compare the effect of blending, I generated an overwrite baseline and a feathered result from the same alignment.

For feathering, I used distance from the nearest source-image edge to create a weight field. The code uses min(x + 1, W − x, y + 1, H − y), normalized by its maximum. Edge weights stay positive so that valid border pixels do not turn into holes. The validity mask sets weights to zero outside the source image. I warped this weight channel along with RGB.

M(p)=wLIL+wRIRwL+wR

At each pixel with a positive total weight, I divide the weighted color sum by the weight sum. Where only one image contributes, its color is preserved. Where neither contributes, the exported pixel stays transparent. Overwrite instead selects the right image wherever it is valid.

Inspect feathering and mosaic compositing
def feather_weights(image):
    height, width = image.shape[:2]
    y, x = np.indices((height, width), dtype=np.float32)
    distance = np.minimum(np.minimum(x + 1, width - x), np.minimum(y + 1, height - y))
    return distance / distance.max()


def create_mosaic(left, right, H):
    corners = np.vstack([checked_corners(left, H), image_corners(right)])
    shape, origin = canvas_from_points(corners)
    numerator = np.zeros((*shape, 3), dtype=np.float32)
    denominator = np.zeros(shape, dtype=np.float32)
    baseline = np.zeros((*shape, 3), dtype=np.float32)
    overlap_count = np.zeros(shape, dtype=np.uint8)
    for image, transform in ((left, H), (right, np.eye(3))):
        #warp the weight field with exactly the same coordinates as the RGB channels
        packed = np.dstack([image, feather_weights(image)])
        warped, valid = warp_to_canvas(packed, transform, shape, origin, 'bilinear')
        weight = np.where(valid, warped[:, :, 3], 0)
        numerator += warped[:, :, :3] * weight[:, :, None]
        denominator += weight
        baseline[valid] = warped[:, :, :3][valid]
        overlap_count += valid.astype(np.uint8)
    mosaic = np.zeros_like(numerator)
    valid_output = denominator > 0
    np.divide(numerator, denominator[:, :, None], out=mosaic, where=valid_output[:, :, None])
    return mosaic, valid_output, baseline, overlap_count, origin
Reflection

What I learned

A smoother seam is only one part of a successful mosaic.

Before comparing the results, I expected feathering to make the mosaics look better everywhere. Instead, I found that it improves the transition between images but can make misalignment more noticeable.

In mosaic 1, the seam becomes less obvious, but the lettering and window bars show ghosting. In mosaic 2, overwrite keeps sharper details, while feathering produces doubled text and fence bars. In mosaic 3, feathering hides the boundary through the artwork more effectively, although some softness remains.

The main thing I learned is that blending and alignment solve different problems. Feathering can soften a seam, but it cannot move mismatched features into the correct positions. The coverage maps help show where both images contribute, but they do not tell me whether those images are accurately aligned.

I also learned that staying in one place and rotating the phone is a useful capture strategy, but small changes in the camera center can still matter. Since these scenes contain surfaces at different depths, one homography may not align every feature if there was some translation. The images also contain reflections and exposure differences. I cannot identify the exact contribution of each cause from the final results alone.
